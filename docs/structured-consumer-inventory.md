## Pilot and contract seams

Live API evidence comprises shared territory reference plus service registry, service × mode share facts, building ramp and building grid. Their semantic grains/readers are listed above; the physical layouts are not permanent contracts. Publication markers/content versions and associated descriptor/source metadata form a seam: independent table versions, coherent snapshot reads, retry-safe changed-table publication. Preserve this behavior under ADR-0037; do not treat old combined markers or pilot table names as catalogue design.

## Shape candidates and unknowns for #590

- Ordinary scalar observation -> constrained scalar candidate; complete multidimensional profiles (age, DPE) and sparse categorical collections (activities, grants) need distinct completeness/absence declarations.
- Declared detail/profile -> constrained detail candidate only if descriptor owns allowed axes/order, denominator, units and comparison facet.
- Ordered year/threshold/state series -> series candidate; null points, observed period and vintage remain distinct. OCS-GE state endpoints can have multiple departmental vintages; DVF pooled headline is not its annual series.
- Named reference series (e.g. connectivity comparison reference) is not a territory measurement. Two-axis relations, bivariate evidence, BPE equipment cases, programme membership and top-activity lists may require dedicated shapes; settle based on active-reader evidence, not generic EAV.
- Product owner decisions: which published indicators/pages survive; current use of legacy `histoires` fields versus `ThemeContent` must be verified field-by-field (Story selection is retired; no such product decision is reopened); which source/freshness fields are user-visible. Unknown means unresolved, not retire or migrate approval.
- Engineering decisions for #590: contracts for units, null/suppression/support counts, complete-vs-sparse profiles, multi-source provenance, level/facet/direction metadata, named reference identities, and relation/evidence grains. Do not broaden DDL before exercising representative scalar, complete profile, incomplete series, multi-vintage state, sparse collection and relation readers.
