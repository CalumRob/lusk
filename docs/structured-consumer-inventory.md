### Fixed-scope `rang_*` consumer and retirement boundary

The static indicator fields `rang_epci`, `rang_dep`, `rang_reg` and their `_n` group sizes are fixed-scope compatibility values, not generic slots for any comparison rank. Their readers are conditional, not categorically static or API-backed:

- **Acquisition/configuration:** `scalarCohortEnabled()` selects the cohort path only when `VITE_SCALAR_COHORT_API === '1'` (unset/off otherwise). `app/README.md` documents normal dev/build commands as enabling the registered scalar-cohort API; Vite proxies `/api`. Deployment-specific overrides/effective deployed build values were not inspected. On the indicator page, `IndicateurPage.vue` overlays facts from the cohort response for a selected registered scalar; on the map, `CarteView.vue` removes static rows for a selected registered layer and uses cohort facts when ready (leaving rows absent while that API read is pending or failed). Non-API and unregistered paths remain static. These enabled code paths target the scalar-cohort route family retired by the current backend contract; this source inventory is not live behavior verification.
- **Fiche consumers and helper:** `app/src/components/fiche/IndicatorFigure.vue:69-70` and `FigureOffreCyclable.vue:80-84` call `detailsRangEnContexte()`. In `app/src/payload/selectors.ts:561-573`, the helper uses `comparaisonApi` rank, size and scope when present; only when absent does it fall back to the first non-null legacy `rang_epci`, `rang_dep` or `rang_reg` field. On cutover, an API-authoritative reading must not silently display those legacy fields if its scoped comparison is missing.
- **Other browser consumers:** `app/src/carte/popup.ts:67-90` calls `rangEnContexte()`, which follows the same API-comparison-first, legacy-fields-second rule (`selectors.ts:538-545`). `app/src/indicateurs/explorationModel.ts:188-200` reads published rank/group sizes only when `usePublishedRanks` is true; the argument defaults to false, in which case the model calculates ranks from its input facts. These paths can therefore consume different rank sources depending on the selected acquisition and mode.
- **Producers:** shared rank computation is in `pipeline/R/compute.R`; economy attaches ranks in `pipeline/R/analytics_economie_ranks.R`; Mobility produces/attaches its rank fields in `pipeline/R/theme_mobilite.R`.
- **Validation, not product use:** `pipeline/R/verification_donnees_reelles.R` and `pipeline/tests/testthat/test-analytics-economie-ranks.R` / payload contract tests validate rank values, missingness and group sizes. These checks are not product consumers and do not by themselves justify retaining the columns.
- **Deletion gate:** trace `rang_*` field projection through `pipeline/R/modeles_lecture.R` and every model/export reader before deleting the producer outputs; the current source audit does not establish whether generated model/export outputs project those fields. Keep the fixed-scope fields only as migration parity evidence until each conditional browser consumer has equivalent behavior and this projection trace is resolved. Each acquired comparison owns the rank for its own declared/resolved scope: never populate a retired fixed-scope `rang_epci`, `rang_dep` or `rang_reg` (or `_n`) field from a comparison over a different scope.

## Resolved boundaries and remaining evidence

1. **Presentation/content and factual metadata:** stable headings, explanatory copy, display labels, page/subgroup organisation and figure presentation are app-owned content/config; ordinary edits need no R publication or generated metadata/versioning framework. Numeric facts and factual semantics remain producer/API-owned. Existing theme JSON and Sources readers are recorded above; this boundary does not claim their browser migration is complete or authorize removing publisher inputs.
2. **Territory reference and geometry:** retain one compact generated territory reference from the same canonical source as the database for search, directories, names, hierarchy/navigation, relationships and identity lookup; #582's measured search exception remains and no directory API is required. Geometry and map masks have separate dispositions and are not approved by this reference decision.
3. **Raw population facts:** bounded raw population read capability is a specifically identified gap under separate investigation. The territory-name search route and derived indicator facts do not settle it; do not invent an endpoint or fold the gap into a generic serving project here.
4. **Generation retention:** current/database-published/rollback references and a retention/GC policy remain to be reconciled before pruning immutable generations.
5. **Catalogue/serving evidence:** declarations establish accepted resource identity and exclusion accounting, not successful publication for every fact, scope, map layer or page. Current app source still contains retired-route callers and static dependencies; per-consumer value/status/axis/provenance and mounted cutover evidence remain #627 work.

### Recompute source counts (Python standard library)

Run from the repository root. The source maps are authoritative; this prints declaration counts, not a second registry or a runtime publication assertion.

```powershell
@'
import json, pathlib
files = sorted(pathlib.Path("pipeline/inst/extdata/theme-metadata").glob("theme_*.json"))
rows = []
for path in files:
    metadata = json.loads(path.read_text(encoding="utf-8"))
    sources, records = metadata.get("sources", {}), metadata.get("source_records", {})
    for key in metadata.get("indicator_keys", []):
        source = records.get(sources.get(key), {})
        disposition = source.get("serving_disposition", "retained")
        rows.append((metadata["theme"], key, disposition, key in metadata.get("indicator_pages", {})))
print(f"theme/key pairs={len(rows)} unique={len(set((t,k) for t,k,_,_ in rows))}")
print(f"retained={sum(d == 'retained' for _,_,d,_ in rows)} excluded={sum(d == 'excluded_legacy_accessibility' for _,_,d,_ in rows)} pages={sum(page for *_,page in rows)}")
'@ | py -3 -
```
