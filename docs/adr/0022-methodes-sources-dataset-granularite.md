# La table des sources de Méthodes se rend par jeu de données, millésimes imbriqués

The Méthodes sources table rendered **one row per vintage** — the exact mirror of the pipeline's `vintages.json` download trace. A single dataset like DVF therefore appeared **20 times** (5 millésimes × 4 départements) with **identical freshness** (version = year, `date_publication = 2026-05-18` everywhere) — the per-département split is a download artifact, not a domain fact (verified #160, 2026-08-06). The restructure of `/methodologie` (#206) needed the table to express the dataset as the unit, while the freshness facts remain per-vintage.

**Decision (user, 2026-08-11):** the sources table renders at **dataset granularity** — one header row per dataset (nom, éditeur, thèmes, URL, the indicator↔source consumers) with its **vintage rows nested beneath** (editorial `libelle` + the freshness facts: version, dates, licence). The collapse is **app-side only**: `vintages.json` stays the 20-line download trace untouched ("the app renders; the pipeline computes"). A source's URL lives on the **header only** — it is a dataset fact, never repeated per vintage. The consumers/matrix lists **indicators only** (stories have no source field yet — gated on #74 / #308, their direction is mid-rework).

The honesty rule that makes the collapse safe: **a dataset collapses only where its vintages carry identical freshness** (DVF → 1 header, its 20 rows absorbed). Where vintages carry **distinct** facts (OCS-GE: 8 state archives, different millésimes per département, + 3 correction patches), they stay **visible children** — collapsing those would lie about the data.

**Considered options:** (1) pipeline-side collapse (`vintages.json` one line per dataset) — rejected: the per-département rows are the real download trace, the seam is "the app renders, the pipeline computes", and a published collapse would lose the OCS-GE per-millésime honesty; (2) app-side flat grouping (keep 20 identical-looking rows, group in render) — rejected as the *first* option because it does not solve the repeated-consumers problem; (3) **dataset header + nested vintages, app-side — chosen**: one logical row per dataset, freshness facts stay per-vintage where they differ, DVF's identical rows collapse into the header (zero information lost), OCS-GE's distinct millésimes stay honest children.

**Consequences:** the sources table is rebuilt around the registry's generated families (`sourcesDvf`/`sourcesDpe`/`sourcesOcsGe`/`sourcesOcsGePatches`) gaining a per-vintage editorial `libelle` (French: « Millésime 2021 · Côtes-d'Armor (22) »). The dataset identity is the jeu: DVF and DPE are one jeu each, and OCS-GE is ONE jeu — the 8 state archives AND the 3 correction patches are all vintage lines of the same header (the patches share the states' `dataset` key, review #361; their freshness/millésime facts differ, so all 11 rows stay visible children). Per-vintage anchors (`#source-<id>`) stay on the children — the fiche's future deep-links keep working per-vintage. The dataset header carries the dataset anchor if needed. #160 closes as absorbed by #206 (its "one line per millésime vs one line unique" seam question is resolved: app-side, unique header + nested vintages). The parity contract (`methodes-parity.spec.ts`, registry-level) is untouched; the view/selector specs (`methodes-sources.spec.ts`, `methodologie-view.spec.ts` counters) are updated for the new structure.
