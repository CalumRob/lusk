# DPE shares: regime breakdown stays a Méthodes caveat; the payload keeps a seam for a per-year delivery dimension

The ADEME DPE label system changed its rules twice inside the first real Habitat run's data (2026-08-04, issue #22): a 2024 reform altered the label calculation for small dwellings (< 40 m²), and a 2026 change to the electricity conversion factor (2.3 → 1.9) made labels generally more favorable for electric heating. The pipeline already carries both DPE dates (`date_etablissement_dpe`, `date_derniere_modification_dpe`) through the data layer precisely so this question could be answered (spec user story 15). The first real run confirmed the three label regimes (pre-2024 · 2024-2025 · 2026+) share the same A–G shape — middle-heavy, with a smaller F/G tail in newer regimes — so the headline F/G share is not distorted by the mix.

**Decision (user, 2026-08-04):** the **per-regime DPE breakdown stays a Méthodes caveat — no payload slot** (narrow payload, `principles.md` §5). The fiche keeps the single headline figure; Méthodes documents that the F/G share mixes three label regimes and that newer DPEs are systematically more favorable. The per-regime data remains in the cache, computable later, never served.

**But the payload keeps a seam for a per-year delivery dimension.** The user opened space for a future payload carrying the **delivery year** (année d'établissement du DPE) — a UI button switching between years to show the distribution's evolution — explicitly *not* the regime breakdown. This mirrors the DVF precedent already in the payload: a pooled headline plus per-year `detail` rows (`prix_m2`, `ANNEE_DVF`). A future per-year DPE distribution (`distribution_dpe` gaining a year dimension, or a sibling key) follows the same proven shape; it is not built now, only kept possible.

**Considered options:** (1) publish the per-regime breakdown (3 coarse period buckets) — rejected: adds payload complexity, each regime thins to suppression scale at small communes, and the app would need to explain three bars for a caveat Méthodes already covers; (2) **Méthodes caveat for regimes + seam for per-year delivery — chosen**: the honest comparability warning lives in Méthodes, while the evolution view the user actually wants (year over year, driven by a UI switch) remains expressible in the contract later.

**Consequences:** no payload change in this run; `distribution_dpe` stays 7 rows per territory (A–G); the DPE cache keeps both dates (already the case); a future ticket can add the per-year dimension without touching the download/cleaning layers. The Méthodes page gains the regime caveat line.
