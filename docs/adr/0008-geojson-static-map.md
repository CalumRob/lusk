# Map geometry ships as static GeoJSON — not PMTiles

The legacy mobility dashboard (the app's porting source) serves its map data as **PMTiles** archives (`PMTILES_URLS.COMMUNES/EPCIS` via env vars, the `pmtiles.Protocol` registered once in MapExplorer/EntityMap). The original assumption was that Lusk inherits that pattern. The v1 reality: Lusk covers **~1 200 communes + ~62 EPCI + 4 départements + the région** — a few thousand features, nothing more. PMTiles pays for itself when the data is *large* (the legacy app pushed 1.2M points) or when it must serve France-wide later; neither applies to v1, and the PMTiles toolchain (tile generation, source-layer naming, protocol registration, per-archive versioning) is a recurring tax the payload doesn't need.

**Decision (user, 2026-08-03):** the map reads **static GeoJSON files under `/data/`** — `communes.geojson`, `epcis.geojson`, `departements.geojson` (+ région) — produced by the pipeline from **Admin Express** (data.gouv, Licence Ouverte — no ODbL wrinkle, matching the product's open-data identity), filtered to Bretagne and simplified. The app loads them as plain MapLibre vector sources; features carry the `territoire` code so the map joins the fiche payload's KPIs for popups (name + 2–3 KPI + "Voir la fiche"). The basemap was initially CARTO Voyager (raster CDN, attribution "© OpenStreetMap contributors"), matching the legacy app — **superseded by ADR-0018** (Etalab positron vector, ODbL, local vendored style). The legacy MapExplorer/MapSidebar/MapLegend shell ports unchanged; only the PMTiles protocol plumbing is swapped for GeoJSON sources.

**Considered options:** (1) PMTiles under `/data/` — rejected: the toolchain cost only earns its keep at scale; 1 300 rows is squarely in plain-GeoJSON territory, and the previous project's PMTiles friction (protocol, archive generation) is a known tax; (2) **GeoJSON in the static payload — chosen**; (3) WMS/Feature-API services (Kartenn's mViewer stack) — rejected: a runtime GIS server contradicts the static-first architecture (ADR-0003).

**Consequences:** the map is a **later milestone** (fiche-first build order — `site-map.md`); geometry rides the pipeline's publish step (a pipeline issue, not an app issue); the payload contract is unchanged (geometry is a separate artifact, not a table); if Lusk ever goes France-wide (~35 000 communes), GeoJSON stays workable per-département or can graduate to PMTiles then — nothing is foreclosed. See also ADR-0007 (the fiche's Aperçu tab, which the `territoires.epci` column supports).
