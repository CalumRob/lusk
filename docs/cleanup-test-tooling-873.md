## 1. Injected payload test-loader defaults are demand-driven (merged union reconciled)

`usePayload`'s default start request is now `attendre` for **every** consumer, injected test loaders included; only the no-wait-set form retains the historical full-set default (`app/src/payload/usePayload.ts`). The previous injected-loader full-store eager start was test-only — production was already demand-driven — and its removal revealed a real production gap, resolved by the owner decision recorded here:

- **Standalone carte theme tabs (owner decision, 2026-11-02).** CarteView's theme tab bar (`themesPresent`) and `?theme=` presence gate read the six themes' `indicateurs_*`/`histoires_*` sections — which no production surface loads since #868/#871 — so a cold `/carte` visit had lost its tab bar (the implicit eager default masked this). **The owner's selected option (verbatim: `Carte requests its sections (Recommended)`) authorizes exactly this: an explicit `demarrer` for the `indicateurs_*/histoires_*` files its tab bar renders, with the stated carte-only static-download cost** (question/answer transcript preserved in the review evidence: `E:/Temp/opencode/serving-cleanup-20261102/review-877-1d94c77f/owner-answer-clarification.md`). Separately — as an implementation detail of the same change, not part of the option's literal wording — `FICHIERS_DEMARRAGE_CARTE` also starts the six `theme_<theme>` metadata files, because the carte's existing store-side consumers read them with no acquisition fallback of their own: `chargerRangCarte`'s rank page descriptors (`payload.themeMetadata[theme].indicator_pages`) and the programmes presentation metadata merge. Without them the retained map-rank tests fail demand-driven (the rank read fails closed on absent store metadata). No runtime acquisition semantics changed beyond the carte's own start set; the wait-set remains the render gate and the fiche stays API-only. The retained ADR-0019 tab bar is restored in production, and the mounted carte/map specs pass demand-driven.
- **Store-seam regressions pin both defaults** (`payload-store.spec.ts`): a narrow wait-set with an injected loader starts only its files (plus the standard `territoires-metadata` warm rule) and leaves unstarted sections at their honest empty state; the no-wait-set form's start is pinned as the **COMPLETE expected request set** — the six shared files, presence discovery (`indicateurs_*`) for every canonical theme, and the `histoires_*`/`theme_*` pair only for the fixture's present theme — asserted by exact set equality so a missing or extra start is caught (not a `toContain` sample). Tests whose genuinely-needed background files were previously implicit now request them explicitly, each with a comment naming its subject (large-theme ingestion, pending/scoped background failures, presence-drift chains, scoped retry). One previously-vacuous test (background transport failure) is genuinely exercised again. No test was blindly made eager; no acquisition architecture changed. The shared-store seam itself (`creerMagasinPayload`, staged starts, presence transitions, recovery) keeps its dedicated suites (`payload-store-overlap`, `payload-store-transitions`) and the production-path `indicator-read-model-route` spec, all green.
