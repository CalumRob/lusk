# Lusk — Observatoire des territoires bretons

The shared language for Lusk, a public open-data observatory covering the four Breton départements (22 · 29 · 35 · 56). It presents a "fiche d'identité" for each territory — communes, EPCIs, départements, and the region — across six themes (Mobilité, Démographie, Habitat, Économie/Emploi, Milieux, Programmes et subventions), and a data-first **Page d'indicateur** for each published indicator, followed across comparable territories (ADR-0024). Built from open data with visible freshness; navigation: Territoires · Indicateurs · Sources · À propos.

## Territories

**Territoire**:
The object of analysis: a Commune, an EPCI, a Département, or the Région (Bretagne).
_Avoid_: Entité (internal code-level term), zone

**Fiche d'identité**:
Legacy product vocabulary for the current site: the territory's existing page with six theme tabs. The prototype replacement no longer treats this as the canonical product concept; new work uses **TerritoryFacts** and **TerritoryContent** until a new user-facing name is chosen.
_Avoid_: Page d'indicateurs, profil, dashboard

**TerritoryFacts**:
The prototype's normalized, presentation-neutral account of a territory's available facts for one theme or subgroup: identity, values, time, provenance, and any declared comparison context. It is the input to **TerritoryContent**, not a payload-shaped record, an all-themes object, or a renderer prop.
_Avoid_: raw payload, fiche data, Story input

**TerritoryContent**:
The prototype's presentation-neutral semantic account of what can be said about a territory within one theme: ordered subgroups, their indicators and evidence, and optional **Lectures** resolved purely from **TerritoryFacts**. It is complete at subgroup level, represents unavailable content honestly, does not fetch data, and does not prescribe the Cahier, pages, cards, margins, or other presentation placement.
_Avoid_: FicheContent, Cahier content, view model


**Aperçu**:
The fiche's former default, cross-theme tab.
**Status (2026-08-21): retired.** Aperçu no longer exists as a fiche tab; **Programmes et subventions** replaces it as the first/default theme (ADR-0024). Population, density, area, and composition are removed with it and do not move into a persistent fiche header (prototype #400 verdict: Remove). The record below is the historical design, kept so earlier decisions resolve — no part of it is current behavior.
_Historical record 2026-08-03 → 2026-08-21:_ the tab ran on the general (brand) theme and was deliberately not a theme block: a **rundown** (decided 2026-08-07) — the territory's identity, what's happening there, and where to go next. Concretely: the **identity anchors** — population, densité, superficie — a uniform set for every territory type (rendered from a pipeline-published `apercu` table, never derived in the app; deliberately NOT theme facts: part 65+ was dropped 2026-08-07, age belongs to the Démographie theme block), the **Composition** element (one level down, count + link — EPCI → « 43 communes » → `/communes?epci=…`; département → « 17 EPCIs » → `/epcis?departement=…`; région → the 4 départements named inline; commune → « Voir les communes de son EPCI »), and the **Programmes et subventions** element. **No ranks on the identity anchors** — ranks are the theme indicators' job (ADR-0015); superficie is a size fact with no desirability direction, and comparison is the themes'. It was never an "under construction" state. **Aperçu was a fiche concept — the carte had no Aperçu tab** (2026-08-10, ADR-0019): the map's first tab became the renamed « Programmes et subventions » layer group (the carte has no selected territory, so a "rundown" has nothing to run down; the identity anchors never map). The `apercu` table still ships in the payload and feeds only the popup of the spared standalone carte.
_Avoid_: Vue d'ensemble, overview, accueil (the landing page, not the tab)

**Story**:
**Retired product concept (2026-08-28).** Story selection, candidate pools, and salience no longer define the fiche: every territory uses the same underlying data and the app determines the data-deterministic text that presents it. `story_key`, `salience_reason`, `histoires`, and related pipeline fields remain historical/schema vocabulary until the payload is migrated; they must not become new product-side ownership rules.
**Lecture**:
The text presentation of a subgroup's data: a **Marelle** and its associated prose, arranged deterministically by the app from the available facts. A lecture may have figures as evidence, but it does not require every subgroup to have prose or every figure family to be implemented. The lecture is a presentation of data, not a pipeline-selected Story.
_Avoid_: Story (retired product concept), récit, insight

**Marelle**:
The short, prominent title that opens a lecture — the phrase that names the tension or question the following prose and figures make readable. A Marelle and its prose form one **Lecture**; the Marelle is not a separate reading.
_Avoid_: headline (generic), titre de figure (a figure title names evidence), Story

**Figure textuelle**:
A data-deterministic arrangement of words — Marelle, prose block, emphasis, ordering, and wording — that presents facts with the same deliberate role a visual figure presents them. It is resolved by the app's lecture grammar from facts, never copied as arbitrary template prose into a Vue surface.
_Avoid_: copy, microcopy, editorial text (too narrow or too unstructured)
_Avoid_: Récit, histoire (too generic), insight, feature
> _Schema note:_ the pipeline's second payload table is named `histoires` (and `compute_histoires`, `story_key`). That is legacy internal French plumbing. Do not "fix" the schema name in the same change as the lecture grammar; migrate it only when the payload seam is deliberately changed.

**Figure family**:
A reusable semantic evidence shape shared when different content needs genuinely the same kind of figure. The prototype does not inherit a fixed list of families: families are defined case by case after surveying every theme subgroup and relevant **Page d'indicateur** need. A family describes evidence meaning and data shape, not a Cahier or indicator-page layout.
_Avoid_: chart style (visual treatment), component (implementation), the current eight-family list (historical production contract under review)

> _Glossary migration note (2026-08-28):_ older theme entries below may still describe a default Story, a Story candidate, or salience. Those descriptions are historical records, not current product rules. The current product vocabulary is **Lecture**, with its **Marelle** and data-deterministic prose resolved by the app.

**Tension**:
The product-wide design principle (adopted 2026-08-06): an indicator or Lecture earns its place on the fiche by reading a **tension between two forces**, never a bare state. The principle was already latent in the product — Mobilité's flagship reads car access against non-car access, Démographie's trajectory reads attract against renew, Économie's dortoir ratio reads work against residence, Habitat's energy story reads performance against passoire — it is now named and prescriptive. What it changes: lecture design (a Lecture must read a tension), indicator selection ("what does this number argue *against* on the same fiche?"), and the documentation framing of how a theme is built (now Sources + each page's « L'indicateur »). The tiering is uniform across all themes: **binding on Lectures, aspirational for indicators** — a bare state indicator (densité, prix, mix) is fine as long as the Lecture it feeds reads the tension. The fiche shows both sides of the tension and lets the reader connect them — the computation argues, the product never editorialises.
_Avoid_: Conflit (a tension is productive and analytical, not adversarial), contradiction (same), score (a single normalized number is the opposite of a tension)

**Programmes et subventions**:
The cross-theme fiche element showing the state/regional programmes and legal tools a territory is covered by (ACV, PVD, CRTE, Territoires d'industrie, ORT) and its Région subventions. Displays *membership and grants attributed*, never outcomes. Formerly a cross-theme fiche element rather than a theme block; **now the sixth theme** (status below) — its facts give context to the other themes' blocks, they do not compete with them. ~~**Preferred home (2026-08-03): the Aperçu tab**~~ — superseded 2026-08-21: Aperçu is retired and Programmes et subventions is itself a full theme tab, first and default on the fiche (see the theme status below). **On the carte it is its own first tab (2026-08-10, ADR-0019):** the renamed « Programmes et subventions » tab — the map's membership layers (categorical highlight: ACV · PVD · ORT at commune level, CRTE · Territoires d'industrie · ORT at EPCI) and subventions choropleth (total € per territory, at every level; the per-programme breakdown is commune-only, 2026-08-10 — level-native layers, nothing invented at dép/région). **Scope locked 2026-08-06:** three kinds of coverage, never conflated — **labels** (ACV, PVD — closed-list support programmes), **contracts** (CRTE, Territoires d'industrie — EPCI-anchored coverage), and the **legal tool ORT** (badged only where it adds information); plus **subvention facts** (grants attributed, amount and year — the subvention is data, not merely a link to the portal). **Subvention display (decided 2026-08-06, empirical; reworked 2026-08-10, issue #305):** level-dependent — a **commune** fiche shows the annual total (« X € de subventions attribuées en 2025 » — most recent complete year, decision-dated, anchored on the project's commune) **split by policy area** (`programme_libl`; the median commune-year spans 2 areas, ~77 % span ≤3); an **EPCI/département/région** fiche shows the **single annual total** + the portal link (a by-area split is unreadable there — median 13 areas/EPCI-year). Annual framing only, never cumulative. **The pipeline publishes the FULL per-area split** — the old top-N + « autres » fold is gone (ADR-0013 amended 2026-08-10): the fold is a display decision, so the app shows the **top-5** areas, the rest behind a click-reveal, all in **descending amount order** (app-side sort, `desc(montant)`, libellé tie-break — the pipeline keeps a stable alphabetical publication order). Montants **≥ 1 M€ render compact `X,XX M€`** (2 decimals), below plain `X XXX €` — one formatter for the total and the areas alike. A quiet **context-share** line sits under the total — « X % du total de l'EPCI » on a commune fiche, « du total de la région » on an EPCI or département fiche (the département is NOT a strict EPCI parent — 4 EPCIs span départements, Redon 35+56 — so EPCIs share against the région), none on the région; one decimal, same reference year, only where a total exists. Aggregate totals carry a **provenance line** — « Somme des subventions attribuées aux communes de l'EPCI / du département / de Bretagne » — the « communes de … » phrase a **link to the filtered list** (`/communes?epci=…` · `/communes?departement=…` · `/communes`), reusing the Aperçu Composition pattern; the sum-of-member-communes fact is stated, never left ambiguous (ADR-0013). v1 badge set: ACV · PVD · CRTE · Territoires d'industrie · ORT tool-badges · subventions. The Région's own territorial device « Bien Vivre partout en Bretagne » is **not** a badge — the device name has changed and no structured signatory list exists (research 2026-08-06). **Ladder, three voices (decided 2026-08-06):** EPCI-anchored contracts (CRTE, TI) **cover** every member commune — the downward voice; commune-anchored labels (ACV, PVD) reflect up as **named portage** (see **Portage**); and above the anchor — on **département and région** fiches — neither voice goes flat: contracts and ORT render as **aggregates** (counts of the anchored units, the anchoring units named: « 7 CRTE signés · 2 villes ACV (…) »), never a badge the territory didn't earn. Every fiche answers "what covers this territory?"; the source defines the anchor set (no coverage is asserted the source does not support).
_Avoid_: Programmes & financements (the superseded label — « Programmes et subventions » is the official dataset wording; kept as an alias so the older docs still resolve), Financements (alone — misses the programme-membership half), dispositifs (too jargony), funding (English)

**Theme status (2026-08-21):** Programmes et subventions is the sixth theme, replacing Aperçu as the first/default fiche tab. Its memberships, contracts, legal tools, and grant facts remain facts about public action, never outcomes.

**ORT (Opération de revitalisation de territoire)**:
The legal tool of centre-ville revitalisation (loi ELAN art. 157, codifié CCH L.303-2) — a **convention**, not a label: portée by the intercommunalité and its ville principale, signed with the État and partners, open to any territory, no label required. What it confers: **rights** — dispense d'autorisation commerciale, reinforced préemption, Anah priority, Denormandie eligibility. A well-drafted ACV or PVD convention **vaut ORT** (contains the ORT elements). **On the fiche (decided 2026-08-06):** a tool-badge shown **only where it adds information** — on non-labelled communes inside an ORT perimeter and on EPCIs whose ORT is not carried by an ACV/PVD label. A labelled ACV/PVD territory never shows an ORT chip; its label carries the "convention valant ORT" fact as an accessible rider. Never double-badged with the label it carries.
_Avoid_: Dispositif (overloaded — see Programme), ORT de revitalisation (pleonasm), outil de revitalisation (generic — ORT is the precise name)

**Portage**:
The **upward** ladder voice for commune-anchored labels (ACV, PVD) — the intercommunalité co-signs (*porte*) its labelled communes' projects, so its fiche **names them** (« Porte un projet Action Cœur de Ville (Lorient) · 3 communes Petites Villes de Demain (Hennebont, Languidic, Plouay) ») rather than claiming coverage. **Full naming, never truncated (decided 2026-08-06):** every labelled member commune is named at every level the voice renders; a long list is scrollable, not capped. The verb shifts up the ladder with honesty — the EPCI *porte*, the département and the région *comptent* (« Compte 26 communes Petites Villes de Demain (…) ») — same named-list form, honest verb. The mirror of **coverage** — the downward voice of EPCI-anchored contracts (CRTE, Territoires d'industrie) over their member communes. Decided 2026-08-06.
_Avoid_: Couvert par (the downward voice — wrong for labels), labellisé (the commune is labelled; the EPCI porte)

## Product pages

**Méthodes**:
The former methodology page (`/methodologie`, page title "Sources & Méthodes").
**Status (2026-08-21): retired as a standalone page — deleted by the cutover #410 (2026-08-26), no alias survives.** Indicator-specific explanation lives in **L'indicateur** on each Page d'indicateur; dataset provenance, licences, URLs, vintages, and consumers live on the top-level **Sources** page; project purpose and principles remain in **À propos**; all internal links were migrated (#410, including the payload-owned ones). The documentation duty survives the page: a theme is not "built" until its sources and variables are documented in those homes, never an afterthought (ADR-0024).
_Historical record 2026-08-03 → 2026-08-21:_ the factual companion to the fiches, documenting each theme's sources (with URLs and timestamps) and explaining its indicators and Stories. **Documenting Méthodes was a deliverable of every theme build.** The page covered built themes only; a theme's section shipped with its payload.
_Avoid_: Méthodologie (the route slug, internal), notes de reproductibilité (the pipeline-side design doc, not the page), documentation technique (the code-level docs)

**Carte**:
The interactive map page (`/carte`) — the context-giver ADR-0019 specified (**the entry-point role is retired by the cutover #410 — see the status below**): it answers *where is X, and how does it sit relative to its neighbours?* and hands off to the fiche for depth. **The fiche tells the story, the map gives context** — the two never compete. Its content rule is the **miroir de la fiche**: every number a fiche renders is a layer on the map; the layer list derives from the payload (indicateurs + histoires), never a carte-specific spec (a separate document tracking which variables map was rejected — it would drift from the fiche). Series and distribution signatures (conso_enaf, the prix_m2 vintages, the dens_*/dec_* signatures) are **not** layers — a choropleth needs one value per territory; multi-detail keys (structure_age, DPE, mix…) render as **grouped layers** in the sidebar. Each theme's **default layer is its Story's first scalar** — the scalars the fiche's story actually renders, read from `histoires_<theme>.json` (Démographie → `taux_solde_naturel`, Mobilité → `div_loss_t`, Habitat → `part_passoires`, Milieux → the first artif scalar); story-pool siblings (`div_loss_b`, `delta`…) become sidebar layers. Scales are **computed from the values, never specified per indicator** (rule of three, 2026-08-10): **signed** (`min < 0 && max > 0`) → diverging ramp — the theme anchor at the positive pole, one shared counter-hue at the negative pole, the neutral at zero, per-side tail-test buckets; **heavy tail** (`p99/median > 10`) → log-spaced sequential; **tame** → linear/quantile sequential. First load is the **neutral state** — uncoloured masks, no layer; a visitor lands on a plain Brittany and picks a lens. The tab bar carries the themes plus the **« Programmes et subventions »** tab (renamed from Aperçu — see that entry: membership + subventions layers, level-native). Clicking a territory opens a popup leading with the **active layer's value + its rank-in-context**, then « Voir la fiche »; the level switch **re-joins the same layer at the new level's rows** (commune → EPCI → département, thresholds recomputed); the sidebar search **zooms to the entity and opens its popup** rather than navigating away. URL state: `?theme=` (a theme) and `?onglet=programmes` (+ optional `&programme=` sigle) are mutually exclusive; both absent = the neutral state.
**Status (2026-08-26, bascule #410 + ruling produit) : épargnée mais sans lien.** The standalone /carte is no longer a product destination — the header, footer, home, search, lists and reading figures carry NO link to it (the PO keeps it as a personal exploration tool: routed and fully functional). Maps as a product surface live on each **Page d'indicateur**'s Carte view; the entry-point role died with the cutover to Territoires · Indicateurs · Sources · À propos.

_Avoid_: Map (English), la mappemonde, l'atlas (a different artifact), fond de carte (the basemap, not the page)

**Page d’indicateur**:
The data-first counterpart to the territory-first **Fiche d’identité**: one canonical page follows an indicator across territories instead of gathering every indicator for one territory. It has three stable views — **Repères**, the default automatically regenerated synthesis of distributions, contrasts, extremes, and rankings; **Carte**, the indicator’s spatial view; and **L’indicateur**, its definition, calculation, unit, source, vintage, caveats, and embedded source records. Themes group pages in the indicator catalogue but have no pages of their own. A page covers indicators only: **lectures** remain resolved elements of fiche subgroups until a distinct data-first editorial model for them is understood, but every indicator remains eligible for its own page when a fiche lecture uses or interprets it. Repères and Carte compare one available level at a time — communes, EPCIs, or départements; the Région has its own fiche but is excluded from data-first indicator comparison and never appears as a permanent benchmark. Bretagne is the default comparison universe at each level, not a benchmark value; commune views may narrow to a département or EPCI, and every generated repère, rank, and mapped value follows the same URL-explicit scope. The level is always explicit in the page URL: an explicit URL wins, otherwise the page uses the visitor’s globally remembered level when the indicator supports it, otherwise it falls back to the finest published level; the resolved fallback is written back into the URL. A multi-detail indicator still has one conceptual page: Repères shows the complete indicator and highlights the selected detail, Carte maps exactly that one scalar detail, and L’indicateur documents the whole and its details; the selected detail is explicit in the URL. A fiche's « Explorer » handoff carries its territory as explicit page state plus its niveau when comparable (commune/EPCI/département; the Région, excluded from data-first comparison, carries no niveau and the page resolves its honest fallback) — the facet is never carried, the target resolves its descriptor-declared canonical facet; that territory stays highlighted across Repères and Carte until cleared or replaced, while the comparison scope remains Bretagne by default. Generated prose stays neutral (higher/lower, never best/worst); direction and colour semantics remain declared metadata. Repères follows a closed exploration grammar parallel to the fiche figure grammar: both share each indicator’s semantic family, but the fiche renderer explains one territory while the Repères renderer compares many territories. Scalar, composition, trajectory, distribution, relationship, and profile/list families therefore receive purpose-built cross-territory presentations rather than per-indicator branches; controlled special cases are metadata, never component conditionals. Each family’s shared semantic grammar supplies its default comparison behavior (sole scalar, latest trajectory endpoint, distribution median, and so on); indicator metadata declares only semantic roles or exceptions the family cannot infer, never repetitive per-indicator facet configuration. The published theme descriptor is the authoritative runtime contract for catalogue membership, conceptual details, labels, units, direction/colour treatment, supported levels, page presentation, and methodology/source references; planned but unpublished documentation never creates a page. The map is a view of the indicator, not a separate destination; the standalone **Carte** page keeps its route but carries no user-facing link (PO ruling 2026-08-26 — spared as an unlinked exploration tool, superseding ADR-0019's standalone-destination status without deleting it, see **Carte**).
_Avoid_: Page de données (too broad), fiche d’indicateur (confusable with Fiche d’identité), faits marquants (implies editorial selection), Comprendre (sounds like another interpretive data view)

**Facette résumée**:
The declared comparison facet of a distribution **Page d’indicateur** (#440): ONE published scalar of the theme — often another indicator than the page's own key (`part_passoires` résume `distribution_dpe`) — whose public label and declared unit drive the **Repères** between-territory comparison and pilot Carte, extremes, and table ordering. Declared in the page descriptor's `comparison`; always named to the visitor; a distribution is never compared by its own bins.
_Avoid_: summary (English), indicateur pilote, vue de synthèse

**Signature (Repères)**:
A territory's own within-territory distribution on a distribution page: the closed declared detail list (DPE A→G), rendered all-or-nothing for the selected territory — in its official detail colours where they exist (ADR-0023). Distinct from the between-territory comparison the **Facette résumée** drives; never compared détail par détail across territories.
_Avoid_: modalités (the replaced generic wording — « détails déclarés »), profil, étiquette par étiquette (the DPE-specific phrase — « détail par détail » is the grammar's wording)

**Profil**:
The complete category profile of a territory on a **list**-family **Page d'indicateur** (#439): the closed declared category list from the published descriptor (reseaux — longueur et densité per mode), rendered for the selected territory in DECLARED order, each category with its canonical label and its OWN published unit (a list carries heterogeneous units — km and km/km² — categories never sum to a whole). Four honest states like the distribution signature (#440): no selection affirms nothing, a territory outside the level is « absent », missing categories are « incomplet », otherwise « complet ». One declared category doubles as the comparison facet (« Catégorie comparée ») driving median, extremes, table ordering and Carte through the shared wave-0 seams (direction-aware ex-aequo ranks included); the full profile stays visible above — never reduced to an unexplained score. This Repères sense is distinct from the fiche-side Avoid reading of « profil »: a Fiche d'identité has no profile.
_Avoid_: vue de synthèse (that is the Facette résumée's role, not the profile's), score composite (the rejected reduction of the profile to one number), ordre dérivé des faits (category order is metadata-owned, never fact-derived)

**Relation**:
The declared cross-territory cloud of a **relationship**-family **Page d'indicateur** (#441): two semantic roles (x × y) declared in the page descriptor, each a published theme key carrying its OWN public label and unit — roles are contract fields, never inferred from indicator names, and no raw key ever renders (ADR-0023). The between-territory comparison is driven by the **scalar facet** (`comparison` — a published key with its required public label, mirroring the distribution family's Facette résumée): it alone drives median, extremes, table ordering and Carte; the relation is never presented as a single-score model. Cloud points and table rows resolve to the same territories by construction — same facet-comparable population, same direction-aware ex-aequo ranks (#437), highlight and fiche handoff preserved end-to-end; chart scales derive from actual values, and incomplete points are named rather than stacked at fixed coordinates. Four honest states like the signature/profil models: no selection affirms nothing, a territory outside the level is « absent », missing coordinates are « incomplet », otherwise « complet ».
_Avoid_: nuage de points (the chart type, not the grammar's sense), corrélation (never claimed — the cloud reads two declared forces side by side), scatter plot (English)

## Themes & indicators

**Thème**:
A data domain contributing a block to the fiche: Mobilité, Démographie, Habitat, Économie/Emploi, Milieux — joined by **Programmes et subventions** as the sixth theme (2026-08-21, replacing the retired Aperçu tab; ADR-0024). **Restored 2026-08-04** — a lens-driven reorganisation (cross-cutting research questions as tabs) was explored and set aside: the classic four keep the fiche instantly legible to its audience. **Milieux added 2026-08-06** as the fifth theme (see **Milieux**) — the dedicated environment/transition block question, open since grilling 2026-08-04, is **resolved**: the environment owns a block *and* is woven across themes. Each theme block is organized into **subgroups** (payload-declared in `theme_<theme>.json`), each carrying a variable number of indicators plus one resolved Story reading. Environmental concerns are woven *across* themes (energy performance in Habitat, cycling in Mobilité, green economy in Économie) **and** concentrated in **Milieux**, which owns the land axis (artificialisation — the "land-use in Habitat" thread, never built, now lives here) and, in a later phase, the water axis.
_Avoid_: Domaine (overloaded), sujet, rubrique

Programmes et subventions is the sixth theme. A theme may contain categorical coverage as well as numeric indicators and may legitimately have no lecture; theme status does not imply an editorial Story.

**Milieux**:
The fifth theme block (added 2026-08-06): the state of the territory's natural milieux. Two axes: the **land axis** (v1 — artificialisation, read as the **état artificialisé** — the OCS-GE *stock* — through the story's **trajectoire par habitant**; ADR-0017) and the **water axis** (designed 2026-08-06, **phased**: built after a water-data research pass — the chain from the tap to the source, commune ← UDI ← captage ← bassin d'alimentation, because a commune's water quality is decided *upstream*, often in other communes). The block's thesis: **environmental problems do not respect communal borders** — land consumption leaks out of constrained centres into the ring (see `docs/research/zan-rennes.md`), water arrives from elsewhere. The **Tension** principle is its spine: growth vs soil on the land side, upstream vs downstream on the water side. Named **Milieux**, not Sols (the earlier name — covers the land axis only) and not Environnement (too broad, the pre-2026-08-06 candidate).
_Avoid_: Sols (the superseded name — the land axis alone), Environnement (the pre-block candidate, too broad), Écologie (the research note's working title, not the product term), Aménagement (bureaucratic — a policy, not a state)

**Hermétique**:
The payload rule that keeps themes independently loadable (ADR-0020, 2026-08-10): a theme's rendering reads only its own `indicateurs_<theme>` + `histoires_<theme>` files (plus the shared `territoires` reference and the shared cross-theme tables — `apercu`, `programmes`, `vintages`, `run-report`). Any fact a theme needs from another theme's domain is **precomputed by the pipeline into the consuming theme's own payload at compute time** — never cross-read, never derived in the app. The apparent duplication (Δpopulation ships in both Démographie and Milieux) is the seam, not waste. It is what the wait-set architecture of « Chargement prioritaire » (#296) depends on: a theme's wait-set is exactly its own pair, never transitive.
_Avoid_: « charger aussi les indicateurs du thème X » (cross-theme loading — the rejected alternative), « dériver dans l'app » (the app renders; the pipeline computes)

**Se densifier, s'étaler, ou s'en aller**:
The Milieux default Story (named 2026-08-06; **the only Story** — a single-story theme like Économie/Emploi: the leakage reading was considered and **skipped 2026-08-06** — the AAV is a statistical perimeter, not a policy lever, and the EPCI fiche's own cloud already shows the intra-EPCI centre-ring gradient; the AAV-level leakage finding lives in `docs/research/zan-rennes.md` as documentation, never on a fiche): reads a territory's growth against its land — **taux_variation_population — Δpopulation annualisée en ‰/an (RP, from the Démographie série historique, le registre Démographie — #306; the raw Δpopulation sign still drives classification; the raw count stays for the prose) × trajectoire par habitant** (the M3/M2 per-capita artificialized-surface ratio, from the **états OCS-GE**) — as exactly one of four readings (re-keyed 2026-08-08 off the flow reading, ADR-0017; the population force annualized 2026-08-10, ADR-0017 amended — the four reading names survive):
  - **Grandir en se densifiant** — population up, per-capita state falling — « la population grandit plus vite que la terre artificialisée »;
  - **Grandir en s'étalant** — population up, per-capita state rising (land grew faster than people);
  - **S'en aller, et consommer quand même** — population down, per-capita state rising (pressure per person still climbing);
  - **Les départs laissent la place à la renaturation** — population down, per-capita state falling — a **measured** decrease (requires `artif_m3 < artif_m2`): the land itself shrank, désartificialisation directly observable.
The land force is the **état artificialisé** — the OCS-GE *stock* at each millésime, never the CONSOENAF flow (the flow reading and the « zéro consommation » test were dropped 2026-08-08 — the consumption-sign axis was degenerate, 99.3 % one-sided; ADR-0017). The supporting figures are **Intensité état** (m² artificialisés / habitant at each millésime) and **Série annuelle** (the CONSOENAF flow — the only annual signal; the « Consommation d'ENAF 2021-2025 » and « Trajectoire ZAN » figures were dropped 2026-08-08, the story now carries the trajectory reading). The chart confronts the territory with its comparison group **at the same scale** (ADR-0011 quadrant cloud): **x = le taux annuel de variation de la population (taux_variation_population, ‰/an — the axis label « Variation de population {periode_pop} (‰/an) », the window derived from periode_pop, never hard-coded), y = Δ(m²/inhab)**, axes crossing at 0 (no median lines), the territory's dot highlighted among its peers, every peer dot hoverable (name + both values) and clickable (opens that peer's own fiche). **All cloud points plot on the rate — never a raw/rate mix**; the prose keeps the raw count (« la population a évolué de +8 000 habitants ») and the classification reads the Δpopulation sign alone — identical for the count and the rate, nothing downstream moves. **Trois horloges** (the extended two-clocks transparency promise, decided 2026-08-08, ADR-0017 — see the entry below): the **population clock** (the shared window 2017→2023, with the bracketing rule — RP 2017 for the initial state, RP 2023 for the final state, never interpolation), the **OCS-GE state clock** (the per-département M2→M3 pair — the millésime-mixing rule), and the **CONSOENAF annual clock** (the annual series, *deliberately fresher*). All three are stamped on the fiche with their own window, named never collapsed; the source records on Sources document the gaps.
_Avoid_: Ce que la croissance coûte au sol (the earlier name — not salient enough), zéro consommation (the dropped flow test)

**taux_variation_population**:
The Milieux story's population force, annualized (decided 2026-08-10, ADR-0017 amended #306): Δpopulation read as an **annualized rate per 1000 inhabitants (‰/an)** — the Démographie register, the same INSEE convention as `taux_solde_naturel` / `taux_solde_migratoire`. Formula: `delta_population / (millesime_fin − millesime_debut) / ((pop_debut + pop_fin) / 2) × 1000` — the duration derives from the two RP millésimes (`periode_pop`, the two-clocks rule, never hard-coded); the population moyenne is the INSEE bracket `(pop_debut + pop_fin) / 2`; a zero population moyenne yields NA, never a division by zero. Computed by the pipeline onto the Milieux histoire line (Hermétique, ADR-0020 — never derived in the app); `delta_population` raw stays published for the prose. The quadrant x-axis reads the rate (label « Variation de population {periode_pop} (‰/an) », the window derived from `periode_pop`, never hard-coded); every cloud point (focal + peers) plots on the rate — never a raw/rate mix; the prose keeps the raw count; the classification reads the Δpopulation sign alone — identical for the count and the rate.
_Avoid_: variation brute (the raw Δpopulation — the axis's pre-#306 reading), « croissance » (claims a direction a shrinking territory's rate does not have), « ×100 hab/an » (the superseded #264 unit — an absolute annualized keeps size: village and métropole incomparable)

**État artificialisé**:
The **stock** of a territory's artificialized land at an OCS-GE millésime (ha; IGN OCS-GE Nouvelle Génération — the official ZAN referential, Licence Ouverte 2.0) — the land force of the Milieux story « Se densifier, s'étaler, ou s'en aller ». A state, never a flow: the stock at M2 and M3 is what the story reads — the per-capita level at each millésime and the M3/M2 per-capita ratio (the **trajectoire par habitant**). Because it is a stock, renaturation is measurable — M3 < M2 is real désartificialisation.
_Avoid_: consommation d'ENAF (the CONSOENAF *flow* — the retired land force), surface consommée (the flow's vocabulary), artificialisation (ambiguous — a stock or a flow; Lusk says état when it means the stock)

**Trajectoire par habitant**:
The M3/M2 ratio of the per-capita artificialized surface (`trajectoire_artif_par_habitant`) — the Milieux story's **second force**, and the exact ZAN question: *is land pressure per person easing?* Falling = densification (« la population grandit plus vite que la terre artificialisée »), rising = étalement. Algebraically equals land growth ÷ population growth; with population falling, a ratio < 1 requires the land itself to shrink (`artif_m3 < artif_m2`) — the reading is only as rigorous as that property. Defined for every territory — a stock-based ratio has no NA hole.
_Avoid_: intensité (the retired flow-based m²-per-added-inhabitant figure — NA for every shrinking or flat territory, ~26 %), trajectoire ZAN (the dropped Δpace figure — the story now carries the trajectory reading)

**Millésime OCS-GE**:
The per-département M2→M3 pair of OCS-GE state years the Milieux story reads (22: 2021→2025 · 29: 2021→2024 · 35: 2020→2023 · 56: 2022→2024), **derived from the data, never hard-coded** — the state window stamped on the fiche (the **millésime-mixing rule**, ADR-0017: a single-département territory states its pair plainly; the 4 of 61 EPCIs that cross département boundaries carry the stated span; the région names its four windows).
_Avoid_: année de référence (too generic), millésime CONSOENAF (the annual series — a different clock), « 2020-2023 » sans département (the window without its owning département is a lie for cross-département territories)

**Trois horloges (the extended two-clocks rule)**:
The Milieux freshness/period discipline (decided 2026-08-08, ADR-0017 — the extension of the 2026-08-06 two-clocks promise): the story and its figures run on **three named clocks, never collapsed** — the **population clock** (the shared window 2017→2023, RP millésimes from the Démographie série historique; the bracketing rule: RP 2017 for the initial state, RP 2023 for the final state, never interpolation), the **OCS-GE state clock** (the per-département M2→M3 pair — the **millésime OCS-GE**), and the **CONSOENAF annual clock** (the annual series, *deliberately fresher*). Each is stamped on the fiche with its own window; the source records on Sources document the gaps.
_Avoid_: deux horloges (the 2026-08-06 rule — the OCS-GE state clock is now distinct from the annual clock), « la même période » (claims a single window the data never has)

**Indicateur**:
A single computed metric within a theme (e.g. densité, part de résidences secondaires, établissements par commune).
_Avoid_: Stat, métrique, KPI

**Rang**:
The indicator's position among its comparison peers — a **direction-aware flat ordinal** within the product's comparison group, rendered **« Xᵉ / Y »** (1er/41 · 4e/8), the group size always shown. **1 = best**: each indicator's desirability direction is known at computation time in the pipeline (low-is-good keys — iso_*, part de passoires, chômage — count from the lowest value; ties share the rank, next rank skips: 1, 1, 3). **Percentiles were retired (ADR-0015, 2026-08-07)**: the raw percentile is direction-blind (Rennes' 0 % isolation read « P1 de l'EPCI » — the best reading as the worst) and scale-hiding over small EPCI groups. Ranks live on the **theme indicators** only — the Aperçu identity anchors carry none (ADR-0015). The **Classement** page (locked long-term) will rank a group by an indicator, filterable by DEP / EPCI. Comparison policy updated 2026-08-10 (ADR-0021): a commune ranks among its EPCI's communes when it has an EPCI (otherwise among regional communes), an EPCI ranks among all Breton EPCIs, a département ranks among the four départements, and the région ranks nowhere — the rendered label names the actual scope. **The rendered chip carries a direction glyph (2026-08-12, #367)** — ▲ « plus = mieux » / ▼ « moins = mieux » — with the **full sentence in tooltip and aria-label: the glyph never carries meaning alone** (color-blind safe, §2/§8 DESIGN.md); each indicator's direction is declared metadata (the descriptor's `direction`) and is documented on its own Page d'indicateur (« L'indicateur »), Sources carrying the dataset provenance.
_Avoid_: Percentile (retired 2026-08-07), notation « P25 », « top X % » (rejected — still hides the group size and the direction)

**L'offre de mobilité alternative**:
The Mobilité block's supply-side sub-block (named 2026-08-06): the infrastructure-offer indicators grouped under one label — **Offre TC** (part des bâtiments près d'un arrêt, Korrigo), **Bornes de recharge** (IRVE — la **comparaison bornes vs stations-service** (EV contre fuel) se construit dans #369, triage 2026-08-12 : numérateur les bornes IRVE (stations, jamais les points de charge), dénominateur les stations-service **BPE B316** — la source officielle (définition INSEE : stations ayant vendu ≥ 500 000 L l'année précédente, petites stations sur volontariat ; dénombrements FACILITIES par commune, l'INSEE recommandant la présence/absence aux niveaux fins) ; ratio publié seulement là où fuel > 0 — bornes = 0 → 0 classé (les égalités partagent le rang, ADR-0015), fuel = 0 → NA avec le texte « Aucune station-service sur le territoire » / « Aucune borne ni station-service » ; BPE B326 (bornes EV depuis 2024) reste la référence officielle de croisement des bornes IRVE), **Stationnement vélo** (places / 1 000 hab, hub Ecolab pris tel quel), **Stationnement voiture** (les PLACES ESTIMÉES depuis la surface des parkings OSM `amenity=parking` — ways fermés + relations, jamais les nodes sans déduplication, jamais `capacity` (porté par seulement 15,7 % des surfaces) — divisée par les facteurs documentés : **25 m²/place** en parc de surface (le module 2,5×5 m = 12,5 m², dégagement inclus), **~11,5 m²/place** en voirie (module parallèle 5×2,3 m, NF P91-100, Héran & Ravalet 2008) — `places_stationnement_voiture_1000` (places/1 000 hab, #369, triage 2026-08-12), direction **moins = mieux** : la part de l'espace public que prend la voiture. Le stationnement de rue MAPPÉ est déjà largement dans les polygones (5 508 aires fermées `parking=street_side` des 38 376 objets — la couche lines n'en porte que 10) ; l'incrément linéaire tagué sur les highways (`parking:lane:*` ou l'ancien schéma, × 2,3 m par côté tagué) s'ajoute à la surface — mais seulement 0,40 % de la longueur routière est taguée : le stationnement de rue NON tagué (la majorité dans les communes denses) reste non mesurable, le biais anti-communes-denses est documenté, pas éliminé ; docs/research/stationnement-voiture-osm.md + stationnement-rue-osm.md), and, since 2026-08-08 (issue #222), **L'offre cyclable** — the Geovelo « Aménagements cyclables » network figure: a headline reading **bike infrastructure as a share of car infrastructure** (« X % de l'infrastructure routière », the bike total ÷ the full `c` network, motorways included) plus **protégé vs partagé bars** (km / 1 000 hab) — the composition of the bike offer, split between space separated from motor traffic (pistes, voies vertes, CVCB…) and shared space (bandes, vélos rues, couloirs bus+vélo…). Never suppressed for small n; a territory with no aménagements shows the 0 as a fact. "What the territory offers," the counterpart to the flagship's "what residents can reach." A label, not a merge — each figure keeps its own vintage stamp and rank-in-context. **Le ratio stationnement vélo÷voiture (HIGH) se construit en deux formes concurrentes** (#369, décision 2026-08-12), la forme retenue étant celle qui lit le mieux sur le réel : (a) **m² vélo ÷ m² voiture** — la surface vélo = places × **2,0 m²/place** (le facteur documenté : arrêté du 30/06/2022 → 1,5 m²/place hors dégagement, MRAe 2024 → 2,0 m² dégagement inclus ; uniforme sur les quatre types d'accroche — les guides dimensionnent l'emplacement par l'enveloppe du vélo, jamais par le type d'accroche, qui est un axe de qualité ; docs/research/stationnement-velo-surface.md) ; (b) **places vélo brutes ÷ m² voiture**. Les deux candidates partagent la direction HIGH ; le carré vélo÷voiture de surface tombe dans la bande lisible (quelques % à ~10 %).
_Avoid_: Équipements (the dropped BPE 229-types indicator — see that entry), infrastructure (too generic)

**Voitures par ménage (motorisation)**:
The Mobilité block's motorisation indicator (reworked 2026-08-12, #367): the household car-ownership split as the **three real parts — 0 / 1 / 2+ voitures, summing to exactly 100 %** (the middle category was missing today, #368). The **car-free share (ménages sans voiture) is the headline** — the part the rank reads (HIGH: plus = mieux) and the figure leads with; the 2+ share is the counterweight the tension reads. The three parts come from the census (RP LOG T12, the CARS dimension, the same source as before).
_Avoid_: « part sans voiture et part 2+ » (the pre-#367 two-part form — the middle category was dropped), taux de motorisation (a single rate hides the composition)

**Perte totale (tot_loss)**:
The flagship's volume reading (the access subgroup, #367): where **perte de diversité** counts the service *types* that leave daily reach, **perte totale** counts the *volume* — the lost-access count per building (the services each building reached by car that it can no longer reach à pied ou en transports en commun), published as the **median over the territory's buildings** (the snapshot's `med_tot_loss_t/b`, aggregated per level by the same weighted-median rule as div_loss, #369). Published in both modes — `tot_loss_t` (à pied ou en transports en commun) and `tot_loss_b` (à vélo, with the same mode-neutrality clamp, bike ≥ transit). The two readings render together on the reading figure. **Direction LOW (moins = mieux), decided 2026-08-14** — the rank reads the lost-access volume like div_loss: fewer lost accesses is better (this supersedes the #367 "the rest → HIGH" default; the descriptors declare it).
_Avoid_: perte saturée (the ADR-0012 working name — opaque), indice (it is a count, never a normalized score)

**Statut d'occupation**:
The Habitat parc-composition indicator (the #367 split of the old `statut_anciennete_taille` regrouping): the résidences principales split **propriétaire occupant / locataire / logé gratuitement**, in shares of the parc. The **part HLM (logement locatif social) is the ranked detail** (HIGH: plus = mieux) — the public half of the market tension (the prix au m² reads the other side). Source: RP Logements (dossier complet).
_Avoid_: statut_anciennete_taille (the retired 14-modality regrouping, #367), logement social (the ranked *detail*, not the indicator)

**Âge du bâti**:
The Habitat energy-state indicator (the #367 split): the résidences principales by **building-era of completion** (avant 1946 · 1946–1970 · 1971–1990 · 1991–2005 · 2006–2015 · 2016 et après), in shares of the parc. The **share of old stock is the ranked detail** (LOW: moins = mieux — old stock is hard to insulate, the direct DPE tension). Source: RP Logements (dossier complet).
_Avoid_: ancienneté d'emménagement (a different dimension — how long residents have lived there, not when the building was built), époque d'achèvement (the raw census wording, not the product term)

**Type de logement**:
The Habitat parc-composition indicator (the #367 split): the résidences principales between **maisons and appartements**, in shares of the parc. The **part appartements is the ranked detail** (HIGH: plus = mieux — dense offer is the counterpart of the étalement tension). Source: RP Logements (dossier complet).
_Avoid_: taille du logement (the pièces dimension of the retired regrouping — a different axis)

**Vingt minutes sans voiture**:
The Mobilité default Story (the flagship's headline, named 2026-08-06): reads `div_loss_t` — *"Sans voiture, X types de services disparaissent"* — the number of different service types that leave the territory's daily reach when the car is removed, always-on for every territory. The name is deliberately editorial ("sans voiture" overclaims the bike — the t-mode is strictly foot/transit); the **« comment lire » carries the precision**: "à pied ou en transports en commun à 20 minutes" — the title seduces, the comment lire tells the truth. Renders the building-level distribution of `div_loss_t` (pipeline density signature, same-scale comparison cloud per ADR-0011) with **both readings marked** — the médiane à pied/en TC (`div_loss_t`) and the lecture à vélo (`div_loss_b`). **The vélo mark appears on every Mobilité story plot, even where the default leads** (it never looks like we forgot bikes) — but it is **never in the default's prose** (decided 2026-08-07). **The analysis behind the story is currently ported** (external code, snapshot output) — adapting it into the repo (re-run distances, review the business-type choices, acquire our own BPE) is **part of production-readiness**, not a future feature (2026-08-07, audit item 59).
_Avoid_: Ce que la voiture masque (considered 2026-08-06, rejected — flat next to the 20-minute image), La dépendance automobile (institutional, not editorial), La perte d'accès (pipeline language)

**Perte de diversité (div_loss)**:
The flagship Mobilité figure (the Story's computation, decided 2026-08-06): the number of **different service types** that disappear from a territory's daily reach when the car is removed — car access minus foot/transit access at 20 minutes, aggregated from the building-level analysis. A *count*, never an index: legible to the élu, defensible to the chargé d'études. Computed for foot/transit (`div_loss_t`) and bike (`div_loss_b`); the bike reading is mode-neutrality-clamped to never be worse than foot/transit. **Indicator mode labels say "à pied ou en transports en commun", never "sans voiture"** (decided 2026-08-06 — the phrase overclaims the bike; the story *title* is the one sanctioned exception, its « comment lire » carrying the precision).
_Avoid_: Indice de vulnérabilité (norm_score — the old log-normalized 0–100 composite, rejected 2026-08-06 as too convoluted), score (overloaded)

**Part des bâtiments isolés (isolation share)**:
The flagship's standard-indicator family (grid, decided 2026-08-06): per service cluster, the **share of a territory's buildings without any access to that service à pied ou en transports en commun at 20 minutes** — `1 − share_*`, the mirror of the access share (`1 − share ≈ pct_iso`; the two are the same fact in loss vs access framing, never two indicators). Five clusters: alimentation, santé, administration, école, banque. The deprivation framing — a territory acts on what its buildings *lack*. Rank-in-context per the fiche contract.
_Avoid_: Taux d'équipement (access framing — the mirror, story-side), part avec accès (same mirror)

**Ce que le vélo préserve**:
The salience-fired Mobilité Story candidate (decided 2026-08-06, name provisional): reads the **bike delta** — `div_loss_t − div_loss_b`, the service types cycling already rescues beyond foot/transit. Fires only where the delta is real (top quartile ~4+ types, top decile ~10; median commune ~1 — no story there). Always reads **realized** cycling access, never potential ("ce que le vélo permet déjà", not "ce que de meilleures infrastructures apporteraient" — the data shows the current network, not a counterfactual). **Renders the same distribution with both medians marked (2026-08-07)** : when the vélo story fires, the plot survives — the foot/transit median and the vélo reading drawn on the building-level distribution, the prose naming both marks. (Previously plot-less: the salience rule hid the default's plot. Now **one chart spec for both stories** — salience leads, never hides.)
_Avoid_: "Ce que le vélo pourrait apporter" (claims a counterfactual the data cannot support)

**Population bretonne joignable en 90 minutes en TC**:
The Mobilité connectivity indicator (grilled 2026-08-24/25, research note `docs/research/accessibilite-extra-communale.md`, fills Notes item 83): the **share of Brittany's population that can reach the territory within 90 minutes by scheduled transit** — train (TGV included), coach, bus and maritime shuttles. Published form: *« Un mercredi de période scolaire, X % de la population bretonne peut rejoindre {commune} en moins de 90 minutes en train, en car ou en bus de mairie à mairie. »* — **no em-dash on the fiche**; direction HIGH (plus = mieux). Renders its cumulative curve (x = travel time, y = share of Breton population) with a **median-Breton-commune reference line**. Computation: r5r schedule-based routing on one real, service-presence-gated date (term-time Wednesday), best departure of the whole service day, walk ≤ 40 min both ends, no car, denominator = all Breton RP population (own commune included). The inbound/outbound arrows collapse into this one number (share-level ρ = 0.99). Lives in the subgroup « L'offre de transports en commun ».
_Avoid_: centralité (structural hubness/betweenness is explicitly not this), indice or score (a share, never an index — the div_loss discipline), accessibilité (overloaded — the flagship owns that word), arrivée en ville (the reservoir working name — superseded)

**Mairie à mairie**:
The connectivity metric's geometry (decided 2026-08-25): journeys are measured from each commune's mairie — DILA Base de données locales geocoding, full 1 202/1 202 coverage including islands BDNB centroids missed. Empirically interchangeable with population-weighted BDNB centroids (ρ 0.93, MAD 0.06 pp); kept for universality and élu-legible narrative. No car leg anywhere in the base metric (a drive equivalent may return as a tension reading).
_Avoid_: centroid (the tested-and-settled alternative), gare à gare (the service-level reading — a different question, not shipped)

**Le meilleur départ de la journée**:
The connectivity metric's temporal semantic (decided 2026-08-25): for each origin-destination pair, the earliest-completing departure across the whole service day of one real date — a term-time Wednesday (p01 over an 07:00–20:00 window in r5r terms). Chosen over morning-only windows (they truncate afternoon connections: Redon −6.3 pp on share@90) and over cross-date selection (date variance empirically nil: Wed+1 week ρ = 1.000 — any term-time Wednesday is the best day).
_Avoid_: temps typique, médiane des départs (p50 semantics — harsher and abandoned), meilleur jour (proven not to exist as a meaningful choice)

**Location quotient (LQ)**:
The signature analytical indicator for Économie/Emploi — labelled **« Spécialisation des établissements »**: a territory's sectoral specialisation in its **establishment fabric**, relative to the Breton average (a territory hosting proportionally more establishments than Brittany in an activity). The LQ matrix counts **établissements actifs, never jobs, never people** — the vocabulary never claims employment or skills. **Built 2026-08-05, continuous, never thresholded** (gate C): it drives the sole Story « Ce que la commune abrite » as the **top-5 specialisations** (top-5, `lq_economie.rds` — raised from top-3 on 2026-08-06: the 4th/5th ranks are still enormous LQs, far above the cell distribution's p90, and they add sectoral diversity to the story), **precomputed by the pipeline — the full matrix never ships to the app** (2026-08-06: the app receives only the precomputed story numbers). **Grain resolved (2026-08-21, issues #154/#428):** the official **NA 2008 A17 aggregate**, reached through the pinned correspondence artefact `naf2_na17_2008` (#426 — INSEE table_NAF2-NA.xls; the join is exact at NAF sous-classe, unknown codes such as `00.00Z` are excluded from the calculation and reported, never silent). The empirical case (`docs/research/naf-grain-lq.md`): median cell n = 13 at A17 against 2 at sous-classe — 16 postes observed over 16 641 cells — so the top-5 no longer reads one-establishment noise (the old grain's real data peaked at 9250×). If the reading ever turns generic again, the next fallback is **A10** — never another NAF prefix. The binary incidence matrix M (LQ ≥ 1, `m_economie.rds`) exists **only as a sidecar** for future relatedness — it never drives the Story. Reference: the Breton average only (gate E — the regional SIRENE cut forbids France-wide); an EPCI's LQ compares **vs other EPCIs**, a département's vs other départements (same-scale reference, decided 2026-08-06 — the region's LQ is degenerate, all ≡ 1, so it carries no LQ Story).
_Avoid_: Indice de spécialisation (non-standard name for the same concept), "what knowledge lies here" (claims skills — the data is only the establishment fabric)

**Relatedness**:
The companion analytical concept for Économie/Emploi: which other territories (or sectors) a territory's economy connects to — "what other places does it synergise with". Method settled: relatedness density + "jumeaux économiques" (top-5 twin communes) from a SIRENE co-location network — see `docs/research/relatedness.md`. **Deferred for the analytical phase (gate F, 2026-08-05)** : no density/jumeaux this phase; the theme's binary matrix M (LQ ≥ 1) is emitted as a sidecar (`m_economie.rds`), ready for it.
_Avoid_: Synergies (product-level, not analytical), similarité

**Chômage (au sens du recensement)**:
The Économie/Emploi block's health indicator (santé, the 2026-08-03 portfolio restored 2026-08-06) — the share of the resident active population aged 15–64 in unemployment, per commune (INSEE RP dossier complet, table EMP T4 → source `DS_RP_EMPLOI_LR_PRINC`, 2023). **Census concept**: NOT the BIT measure of the enquête Emploi (census rates run 2–3 points higher), NOT the France Travail/DARES administrative measure, NOT the taux localisés (enquête Emploi + France Travail, which do not exist at commune level). The census smooths collection over five years: the 2023 value is a quinquennial average. Small samples (< 200) are to be handled with care.
_Avoid_: Taux de chômage localisés (a different, non-communal measure), chômage BIT (the enquête Emploi concept), demandeurs d'emploi (the France Travail register)

**Taille**:
The Économie/Emploi block's size indicator (restored 2026-08-06 from the 2026-08-03 portfolio « dynamique · taille · santé · verdure », replacing the two LQ matrices that had drifted into the block): the **total effectifs salariés au lieu de travail** per commune (Flores **A88**, `effectifs_salaries` summed — the same aggregation the dortoir ratio uses). A raw count with its rank-in-context, like population in Démographie; the *relative* employment reading is the dortoir Story's job, never a second block figure. Payload key **`effectifs_salaries`** (decided 2026-08-06 — the source-native measure name; the French label rides in the app's `NOMS_INDICATEURS`). **Aggregation rule (decided 2026-08-06):** an EPCI/département value is **recomputed from its communes' parts, never the mean of commune shares** — chômage = Σ chômeurs ÷ Σ population active, éco-activités = Σ établissements verts ÷ Σ établissements, effectifs = Σ — the numerators exist in the analytical tables, the pipeline groups them up (the same principle as the LQ's same-scale reference). The Flores lens therefore serves size + the dortoir Story, and `lq_emploi` leaves the payload.
_Avoid_: LQ d'emploi (the employment specialisation matrix — superseded, its purpose split between taille and the dortoir Story), densité d'emploi (the relative reading — the Story's, not the block's)

**Solde naturel**:
The natural component of a territory's population change over a period — births minus deaths. The "natural" half of the Démographie story ("Trajectoire démographique"). Published in the payload both raw (`solde_naturel`) and as an annualized rate per 1000 inhabitants (`taux_solde_naturel` — the two forces the story reads are the rates, not the counts).
_Avoid_: Croissance naturelle (strictly the *rate*; INSEE's term for the variation, not the balance), solde démographique (ambiguous — could mean either balance)

**Solde migratoire**:
The residual component of population change — total change minus the solde naturel; net people moving in/out. Never published at commune level by INSEE — always derived. The "migration" half of the Démographie story ("Trajectoire démographique"). Same payload convention as solde naturel: raw count + annualized per-mille rate.
_Avoid_: Migration nette (the INSEE term, but Lusk speaks "solde"), apport migratoire

**Trajectoire démographique**:
The Démographie Story (renamed 2026-08-04, formerly "Attractive ou fertile ?"): reads a territory's population trajectory as exactly one of four readings by the **signs of its two annualized rates** (solde naturel ‰/an × solde migratoire ‰/an) — the four quadrants: **attire-renouvelle** (both positive — the population renews and attracts), **attire-meurt** (migration positive, natural negative — arrivals mask a dying population), **vide-meurt** (both negative — the population empties and dies), **vide-renouvelle** (natural positive, migration negative — births mask an exodus). Replaced the earlier 2×2 (growth vs the région baseline × dominance), which conflated the reading with relative growth; the reading is now the territory's own two forces, nothing relative. The story's chart confronts the territory with its own context: a cloud of its comparison group **at the same scale** — a commune its EPCI's communes (or its département's, when it has no EPCI), an EPCI the other EPCIs, a département the other départements, the région all its communes — every cloud point hoverable and **clickable (it opens that point's own fiche)**. The story sources itself exhaustively (the série historique for the rates, the base des EPCI for the groups) from the vintages table.
_Avoid_: Attractive ou fertile ? (the old name), quadrant reading (internal), solde démographique (ambiguous)

**Passoire thermique**:
A dwelling whose DPE energy label is F or G. Habitat's 4th indicator is the share of a territory's DPE base in F/G — a share of the DPE base, never of the housing stock (the base over-represents transacted/rented homes; the representativeness caveat is declared in the indicator's caveats (« L'indicateur » de sa Page d'indicateur), and the indicator is suppressed for small n).
_Avoid_: Logement énergivore (looser — no label basis), DPE F/G (the label, not the concept)

**Médiane prix au m²**:
Habitat's 3rd indicator: the median declared price per m² of maison/appartement sales (DVF), pooled over the rolling multi-year window for the headline figure, with the per-year series as its evolution. Suppressed for small n (few sales), never a mean.
_Avoid_: Prix moyen (outlier-sensitive, not the figure), valeur foncière (the raw field, not the figure)

**L'état énergétique du parc**:
The Habitat Story (default — for now the only one; "Pression résidentielle" is deferred until its indicator is properly designed): a territory's DPE distribution read as exactly one of four readings by a deterministic concentration rule — **Parc performant** (concentrated on the good end: A/B/C ≥ 50 %), **Parc intermédiaire** (middle-dominant stock, C/D/E — the residual reading; name provisional), **Passoire énergétique** (F/G ≥ 30 % of the DPE base), **Parc hétérogène** (polarized: meaningful mass on BOTH the good and bad ends — genuinely bimodal, checked first). Thresholds provisional, fixed at the first real run.
_Avoid_: DPE (the source, not the story), isolation du parc (the research angle, not the product term)

**Ce que la commune abrite**:
The **sole** Story of Économie/Emploi (single-story theme, decided 2026-08-06 — the salience pool reduces to one always-on default, ADR-0002) — renamed from « Ce que la commune sait faire » (which overclaimed skills: the data is only the establishment fabric). Reads the **top-5 specialisations** by LQ (top-5, decided 2026-08-06 — the 4th/5th ranks are still huge LQs and add sectoral diversity; grain NA 2008 A17 officiel via la correspondance épinglée, résolu 2026-08-21 — see LQ entry), precomputed by the pipeline, **never recomputed in the app** — the app receives a few numbers per territoire, not the matrix. Published for communes, EPCIs and départements (**the région carries no LQ Story** — its LQ is degenerate, all ≡ 1; its Économie tab renders the block indicators only, 2026-08-12). The title is deliberately fabric-neutral ("abrite" — hosts — stays true whether the underlying measure is establishments or, one day, jobs); the indicator label « Spécialisation des établissements » carries the precision.
_Avoid_: Ce que la commune sait faire (claims savoir-faire the data never measured)

**Le matin, la commune se vide**:
The salience-fired Story of Économie/Emploi (built 2026-08-05, **parked 2026-08-06** — Économie is single-story for now; kept as an analytical artifact + a documentation note, ready for the future multi-story model): reads the balance between workplace employment (Flores **A88**, `effectifs_salaries`) and resident active-occupied (RP Emploi) as a **dormitory ratio** (workplace / resident), commune by commune. Fires on the real tails only — thresholds locked from the real distribution (median 0.3): **dortoir-profond** (ratio < 0.15 — the commune empties by day), **pôle-emploi** (ratio > 1.5 — it fills); otherwise the classification is **équilibre**. The two perspectives stay separate columns (workplace / resident), never merged into one indicator. Not published while parked — the payload carries no classification/ratio/workplace/resident columns.
_Avoid_: Commune dortoir (only the deep-dormitory half — misses pôle-emploi), navettes domicile-travail (the transport reading, not the ratio)

## Data freshness

**Vintage**:
The source identity + version + date shown with every indicator ("BPE 2024 · RP 2021"). What makes the "alive" claim honest.
_Avoid_: Date de mise à jour (only part of it), last_updated

**Jeu de données**:
The dataset identity a source is (DVF, DPE, OCS-GE…) — distinct from its **lignes de vintage** (ADR-0022, 2026-08-11): one jeu de données carries one set of editorial facts (nom, éditeur, URL, thèmes), and may be split across several vintage rows that record its freshness per download artifact (per-département, per-millésime). On Sources the table renders **one row per jeu de données** with its vintage rows nested beneath; a vintage row is a freshness fact, never a separate dataset. A dataset whose vintages all share identical freshness is displayed as its single header alone; where the vintages carry distinct facts (OCS-GE's per-millésime states), the rows stay visible — collapsing them would lie about the data.
_Avoid_: source (the whole concept, overloaded), ligne (the row, not the identity), dataset (English)

**Alive**:
The product promise: light themes refresh automatically on a schedule, the mobility rebuild runs semi-automated on a slow clock, and vintage is always visible. **The flagship is a snapshot, and says so** (decided 2026-08-06): the Mobilité analysis is a frozen computation on a slow clock — the fiche stamps it "Analyse calculée le [date] — se rafraîchit sur un rythme lent", distinct from the light themes' weekly vintage chips; it never mimics fresh-refresh language. Sources documents the slow clock as a first-class fact (the snapshot source's clocks and freshness).
_Avoid_: Live, temps réel (the product is not real-time)

**Watchdog**:
The future component that detects new data releases and triggers the pipeline. Deliberately not built in v1; the vintage table is its seam.
_Avoid_: Cron, scheduler (implementation detail, not the concept)

**Reference source**:
The single source that defines an indicator's freshness — declared per indicator in the theme's indicator table, chosen by the rule "the source contributing the indicator's signature component, never a shared denominator". Each indicator in the payload carries its reference source's vintage.
_Avoid_: Source principale (vague), vintage source (that is the column name, not the concept)

**Run report**:
The per-run record of the automation: per dataset, its status (cron → frais/échec; manuel → à traiter à la main) plus a timestamp. Always committed alongside the payload — the durable trace of what a run did, and the input the notification seam inspects to decide whether the user needs to act.
_Avoid_: Log (transient, not committed), rapport (generic French — ambiguous with product reports)
